A spring is for things that have weight: a sheet coming up, a toggle settling or a card that was dragged and needs to return. A little overshoot, kept small, is what makes it feel like an object instead of a fade.

An easing curve is a fixed path from one value to another over a set time, but a spring is a simulation: it has a target, a stiffness and some friction, and it gets there however the physics says it should. That difference sounds academic until someone puts a hand on the thing.

## Where Springs Earn It

The clearest case is anything that can be dragged. At the moment of release it's already moving with a speed and a direction, so a spring picks that up and carries it home. An ease ignores it and starts from zero on a fixed path, as if the throw never happened.

With the ease, every release looks identical however the card was moved. With a spring at zero bounce, a hard throw comes back fast and a gentle one drifts home. At 0.2 it goes slightly past where it started and settles back, which is the part that makes it feel like it has mass, and at 0.5 it wobbles, which is fun exactly once.

The second case is interruption. If someone toggles a switch and changes their mind halfway through, an ease has to restart from wherever it was, usually with a visible hitch, but a spring just changes its target and turns around with the speed it already had, the way a real object would. Anything that can be interrupted is better on a spring, like a sheet that can be swiped away mid-open or a tab indicator someone clicks across quickly.

The third is anything pretending to be physical: a switch knob, a sheet that slides up from the bottom or a pill that moves between segments. The brain treats these as objects, so they should move like objects.

## When an Ease Is Enough

An easing curve is for things that should arrive and stop: opacity, a colour change, a page transition that shouldn't bounce or a blur that clears.

A spring on a fade usually looks like a mistake, because there's nothing there to rebound. Opacity can't go past 1, so the overshoot either gets clipped, which makes the spring pointless, or it shows up as a flash. The same goes for colour, because nothing in the real world bounces between two colours.

Eases are also more predictable. Coordinating several things, like a list that staggers in or a sequence where one thing waits for another, usually means knowing exactly when each part ends, but a spring's duration is a target, not a promise.

When I'm unsure, I use a short ease-out, and I only add a spring when the thing on screen is pretending to be a thing in the hand.

## A Rough Guide

This is what I reach for first, though it's only a starting point because I change it often.

- A sheet or drawer coming up: spring, bounce around 0.15, about 400 milliseconds.
- A toggle knob or a segmented control pill: spring, bounce around 0.2.
- A dragged element returning: spring, bounce 0 to 0.2, using the release velocity.
- A popover or menu: ease-out, 150 to 200 milliseconds, because a spring here tends to feel like it's showing off.
- Opacity, colour, blur: ease or ease-out, 150 to 250 milliseconds.
- A page transition: ease-out or nothing.

## How I Set Them

I set springs by duration and bounce, not by stiffness and damping, unless I already know the feel I want. Stiffness, damping and mass describe the physics, but duration and bounce describe what actually ends up on screen. Most animation libraries now accept either one, and the second is far easier to reason about.

Duration tells me whether it belongs in a daily action, and bounce tells me how physical it should be. Bounce 0 is a spring that never overshoots, so nothing wobbles, but it still feels softer than an ease because it responds to velocity, and often that's enough.

For interface work I keep bounce low, around 0.15 to 0.25, because higher than that and the control starts performing. It looks great in a recording, but it's already tiring by the second use, which is one use too many.

## The Test

When I'm deciding, I ask one question: does this thing have weight? If it could be picked up, or if it slides, settles, snaps or returns, it gets a spring, and if it appears, fades, changes colour or swaps content, it gets an ease.

Most things in an interface are the second kind, but the few that are the first kind are the ones people touch most, so they're the ones I most want to get right.
