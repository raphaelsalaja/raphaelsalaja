Almost everything on iOS and macOS opens from somewhere. An app grows out of its icon, a folder out of its folder, a window falls into the Dock and comes back out of the same spot, and a Quick Look preview zooms out of the thumbnail you pressed space on. I wanted to know what these have in common and how close the web can get to each of them with Motion, CSS and, for one of them, a canvas. This page is that work: what Apple has said about how they're built, what I could only see by watching, and a sketch of each one for the web.

## What They Share

Apple's Human Interface team gave a talk at WWDC 2018 called Designing Fluid Interfaces, about the gestures they built for iPhone X.[^1] It's the closest thing there is to a written explanation of these animations, and four ideas from it run through every one of them.

### Origin

The talk calls it spatial consistency: "if something disappears one way, we expect it to emerge from where it came."[^1] Every animation on this page is that rule applied. An app leaves the screen by shrinking back into its icon because that's where it came from, and a minimised window comes back out of its spot in the Dock for the same reason.

### Continuity

When an app launches on iPhone X, "the icon elastically stretches down to become the app as it opens. And, it stretches up in the opposite direction as you close the app."[^1] There's one object on screen the whole time, rather than an icon that disappears and an app that appears. In iOS 18 Apple gave apps the same thing as a system transition, a zoom where "the cell you tap morphs into the incoming view."[^2]

### Springs

Apple describes its springs with two numbers rather than stiffness and damping. In 2018 those were damping ("from 100% damping, where there will be no overshoot to 0% damping where the spring would oscillate indefinitely") and response ("how quickly the value will try and get to the target").[^1] The team avoided the word duration on purpose, "because it reinforces this concept of constant dynamic change."[^1]

In 2023 Apple moved to duration and bounce, and said it was "adopting these universally across Apple's design and engineering efforts."[^3] Bounce runs from −1 to 1, where 0 is a smooth spring with no overshoot, and duration is a perceptual duration, chosen to stay put while bounce changes.[^3]

The advice from 2018 still holds: "we recommend starting with 100% damping, or no overshoot."[^1] Their example is the Music app, which opens Now Playing at 100% damping when you tap it, because a tap has no momentum, but dismisses it at 80% when you swipe, because the swipe does.[^1]

### Interruption

On iPhone X you can launch an app, change your mind and "shoot it back home, while I'm launching it."[^1] An animation you can't interrupt makes you wait for it before you can act, and that's the one thing none of these do. On the web this decides the tools more than anything else, because only some of them can be interrupted.

## The Spring I'd Start From

Motion takes a spring two ways. Duration and bounce (or `visualDuration` and bounce) are the easier to read, but Motion's docs say these "don't incorporate velocity", while stiffness, damping and mass do "incorporate the velocity of any existing gestures or animations."[^4] An app closing halfway through opening has to carry the speed it already had, so I'd use the physics form and convert Apple's numbers into it.

The conversion, with a mass of 1, comes from Nathan Gitter's write-up of the 2018 talk:[^5]

```ts title="spring.ts"
// Apple's response (seconds) and damping ratio, as a Motion spring.
// stiffness = (2π / response)², damping = 4π × ratio / response
export function appleSpring(response: number, dampingRatio = 1) {
  return {
    type: "spring" as const,
    mass: 1,
    stiffness: ((2 * Math.PI) / response) ** 2,
    damping: (4 * Math.PI * dampingRatio) / response,
  };
}

// SwiftUI's .spring() defaults: response 0.5, dampingFraction 0.825
export const standard = appleSpring(0.5, 0.825); // stiffness ≈ 158, damping ≈ 20.7
```

The defaults in the last line are the ones SwiftUI documents for `spring(response:dampingFraction:blendDuration:)`, which "preserv[es] velocity from one animation to the next."[^6] They're a starting point, not the values SpringBoard uses for an app launch, which Apple hasn't published.

## Opening an App

Tapping an icon on iOS turns the icon into the app. The icon's rounded square grows to fill the screen, its corners getting relatively smaller as it grows, and the icon's artwork gives way to the app as it goes.

### Building It

The icon and the app are two elements, so the job is to make them read as one. Paul Lewis's FLIP technique is the general answer: measure where the element starts (First), put it where it ends (Last), transform it back to where it started (Invert) and remove the transform on an animation (Play).[^7] Motion's `layoutId` does all four for you: give two elements the same `layoutId` and the new one "will automatically animate out from the old component."[^8]

```tsx title="home-screen.tsx"
"use client";

import { AnimatePresence, motion } from "motion/react";
import { useState } from "react";
import { appleSpring } from "./spring";

type App = { id: string; name: string; colour: string };

const launch = appleSpring(0.5, 0.86);

export function HomeScreen({ apps }: { apps: App[] }) {
  const [open, setOpen] = useState<App | null>(null);

  return (
    <div className="screen">
      <div className="grid">
        {apps.map((app) => (
          <motion.button
            key={app.id}
            layoutId={app.id}
            aria-label={`Open ${app.name}`}
            className="icon"
            style={{ borderRadius: 14, background: app.colour }}
            transition={launch}
            onClick={() => setOpen(app)}
          />
        ))}
      </div>

      <AnimatePresence>
        {open && (
          <motion.div
            key={open.id}
            layoutId={open.id}
            className="app"
            style={{ borderRadius: 40, background: open.colour }}
            transition={launch}
            onClick={() => setOpen(null)}
          />
        )}
      </AnimatePresence>
    </div>
  );
}
```

`.app` is `position: absolute; inset: 0` inside `.screen`, so its last box is the whole screen. `AnimatePresence` keeps it mounted on close so it can shrink back into the icon,[^8] and because the icon stays on the page underneath, Motion crossfades the two while they move,[^8] which happens to be the handover from icon art to app content.

The 0.86 damping ratio is my starting guess, chosen for a small overshoot. Apple's advice would be to start at 1.[^1]

### Corners

Layout animations run on `transform: scale()`, and a scaled `border-radius` stretches with the box, so a 14px corner on a 60px icon would become a 14 × 6.5 = 91px corner by the time it fills a 390px screen. Motion corrects this for `borderRadius` and `boxShadow` as long as they're set through `style` or an animation prop rather than a class.[^8] That's why both radii in the sketch are in `style`: Motion animates the corner from 14 to 40 in real pixels while the box scales.

There's a second way that never scales the content at all: lay the app out full size from the start and clip it down to the icon with `clip-path: inset()`, which takes a `round` radius in the same shorthand as `border-radius`.[^9] Opening is then just the inset shrinking to zero:

```ts title="clip-launch.ts"
import { animate } from "motion";
import { appleSpring } from "./spring";

function insetFor(icon: DOMRect, screen: DOMRect, radius: number) {
  const top = icon.top - screen.top;
  const right = screen.right - icon.right;
  const bottom = screen.bottom - icon.bottom;
  const left = icon.left - screen.left;
  return `inset(${top}px ${right}px ${bottom}px ${left}px round ${radius}px)`;
}

export function openFrom(icon: HTMLElement, app: HTMLElement) {
  const screen = app.getBoundingClientRect();
  const start = insetFor(icon.getBoundingClientRect(), screen, 14);

  return animate(
    app,
    { clipPath: [start, "inset(0px 0px 0px 0px round 40px)"] },
    appleSpring(0.5, 0.86),
  );
}
```

The content doesn't stretch, because nothing is scaled, but it doesn't shrink either: the clip reveals the app at full size rather than growing it, so it reads more like a window opening than an icon becoming an app. `clip-path` also repaints every frame where a transform doesn't. I'd use `layoutId` for the launch and keep the clip for things that should be revealed rather than grown.

Apple's icon corners aren't circular arcs either. Since iOS 13, `CALayer` has a `cornerCurve` of `.continuous`, and SwiftUI's `RoundedRectangle` takes `style: .continuous`, which is the squircle-like corner the icons use.[^10] CSS now has `corner-shape: squircle`, which reshapes the corner inside the area `border-radius` gives it, but MDN still marks it experimental and not Baseline,[^11] so I'd only add it behind `@supports`:

```css title="icon.css"
.icon,
.app {
  @supports (corner-shape: squircle) {
    corner-shape: squircle;
  }
}
```

### Closing and Interrupting

Closing an app on iPhone X is a swipe up from the bottom, and the app follows your finger on the way back to its icon. The talk's tool for where a released gesture should end up is projection: take the velocity and a deceleration rate and work out where the thing would stop if it were scrolled.[^1] Gitter's version of the function:[^5]

```ts title="project.ts"
// Distance travelled after decelerating to zero at a constant rate.
// 0.998 is the value commonly given for UIScrollView's .normal rate.
export function project(velocity: number, decelerationRate = 0.998) {
  return ((velocity / 1000) * decelerationRate) / (1 - decelerationRate);
}
```

With Motion's drag, `info.velocity` is in pixels per second, so the release can decide between going home and staying open from where the flick would land rather than where the finger let go:

```tsx title="app.tsx"
<motion.div
  layoutId={open.id}
  className="app"
  style={{ borderRadius: 40, background: open.colour }}
  transition={launch}
  drag="y"
  dragConstraints={{ top: 0, bottom: 0 }}
  dragElastic={{ top: 0.6, bottom: 0 }}
  onDragEnd={(_, info) => {
    if (info.offset.y + project(info.velocity.y) < -160) setOpen(null);
  }}
/>
```

This is the simplest version that works: it decides on release and lets the layout animation take the app home. On iOS the app shrinks while you drag, before you let go, and I haven't sketched that here.

This is also where the View Transitions API falls short for app launches. It can morph one element into another, but only one view transition runs at a time, and "if a new view transition starts while one is already running, the old transition skips to the end."[^12] A close during an open would jump to fully open first, which is the opposite of what the talk asks for.

## Opening a Folder

A folder on the home screen is a small tile of tiny icons that opens into a large panel of normal ones. It's the app launch again with one difference: the content inside has to stay put relative to the box while the box grows, so the icons grow with it rather than being replaced.

In Motion this is `layout` on the folder and on each icon inside it. A child of a layout-animated element distorts with its parent's scale, and the fix is to give the children `layout` too, so Motion corrects them.[^8]

```tsx title="folder.tsx"
<motion.div
  layout
  className={open ? "folder open" : "folder"}
  style={{ borderRadius: open ? 36 : 14 }}
  transition={launch}
  onClick={() => setOpen(!open)}
>
  {apps.map((app) => (
    <motion.div
      key={app.id}
      layout
      className="folder-icon"
      style={{ borderRadius: open ? 14 : 4, background: app.colour }}
      transition={launch}
    />
  ))}
</motion.div>
```

The class change does the layout (a 3 × 3 grid of 12px tiles closed, 60px open) and Motion animates between them. The blur behind it is a separate element with `backdrop-filter`, animated on opacity rather than on the blur radius, because a changing blur radius repaints every frame.

Control Centre's modules look like the same pattern when one expands into a full panel, so I'd leave it as a demo variant rather than a section.

## Minimising to the Dock

macOS has two minimise effects, Genie and Scale, chosen under System Settings > Desktop & Dock > Minimized windows animation.[^13] Both send the window to a spot in the Dock and bring it back out of the same spot, which is the origin rule again.

### Scale

Scale is the plain one: the window shrinks into its Dock tile. On the web it's a FLIP to a rectangle you measure, done with a transform:

```ts title="minimise.ts"
import { animate } from "motion";
import { appleSpring } from "./spring";

export function minimise(win: HTMLElement, tile: HTMLElement) {
  const from = win.getBoundingClientRect();
  const to = tile.getBoundingClientRect();

  win.style.transformOrigin = "0 0";

  return animate(
    win,
    {
      x: to.left - from.left,
      y: to.top - from.top,
      scaleX: to.width / from.width,
      scaleY: to.height / from.height,
    },
    appleSpring(0.35, 1),
  );
}
```

Restoring is the same call with the values reversed. Scaling a window to a tile changes its aspect ratio, so I'd match the window's aspect inside the tile and centre it rather than squash it.

### Genie

Genie is the only animation here that isn't a rectangle. The bottom of the window narrows into a funnel aimed at the Dock tile, then the window pours down the funnel into it. A transform can't do that, because every row of the window needs its own width.

Bartosz Ciechanowski's BCGenieEffect rebuilt it for iOS with Core Animation, and its README notes that it needs "a clear and logical path which animated view will follow" between the view and its destination,[^14] which is the funnel. On the web I'd draw it on a canvas from a snapshot of the window, one row at a time. Each row of the output samples a row of the snapshot and stretches it to the funnel's width at that height:

```ts title="genie.ts"
type Rect = { x: number; y: number; width: number; height: number };

const lerp = (a: number, b: number, t: number) => a + (b - a) * t;
const smooth = (t: number) => t * t * (3 - 2 * t);
const clamp = (t: number) => Math.min(Math.max(t, 0), 1);

// progress 0 is the open window, 1 is the window inside the Dock tile.
export function drawGenie(
  ctx: CanvasRenderingContext2D,
  snapshot: CanvasImageSource & { width: number; height: number },
  from: Rect,
  to: Rect,
  progress: number,
) {
  const bend = smooth(clamp(progress / 0.4)); // the edges curve first
  const pour = smooth(clamp((progress - 0.25) / 0.75)); // then it slides in

  const funnelTop = from.y;
  const funnelBottom = to.y + to.height;
  const top = lerp(from.y, to.y, pour);
  const bottom = lerp(from.y + from.height, funnelBottom, pour);

  ctx.clearRect(0, 0, ctx.canvas.width, ctx.canvas.height);

  for (let y = Math.floor(top); y < bottom; y++) {
    // How far down the funnel this row is, 0 at the window, 1 at the tile.
    const depth = smooth(clamp((y - funnelTop) / (funnelBottom - funnelTop)));
    const left = lerp(from.x, lerp(from.x, to.x, depth), bend);
    const right = lerp(
      from.x + from.width,
      lerp(from.x + from.width, to.x + to.width, depth),
      bend,
    );

    const sourceY = ((y - top) / (bottom - top)) * snapshot.height;
    ctx.drawImage(snapshot, 0, sourceY, snapshot.width, 1, left, y, right - left, 1);
  }
}
```

Driving it is one Motion value from 0 to 1, drawn on every change, so the genie can be reversed halfway like everything else:

```ts title="minimise-genie.ts"
import { animate } from "motion";

animate(0, 1, {
  duration: 0.5,
  ease: [0.4, 0, 0.2, 1],
  onUpdate: (progress) => drawGenie(ctx, snapshot, from, to, progress),
});
```

The timings (edges for the first 40%, pouring from 25%) and the duration are mine, picked to look right rather than measured. The snapshot is the catch: the canvas needs the window as an image, which means a library that rasterises DOM or the HTML-in-Canvas API I wrote the WebGL motion blur against.[^15] A WebGL version would warp a grid of vertices instead of drawing rows, which also lets the funnel curve smoothly between rows, but the shape of the maths is the same.

### The Bounce

The Dock also bounces an app's icon while the app opens, under the setting "Animate opening applications: Make icons bounce when you open apps."[^13] It's a repeat, not a spring, so it's keyframes with an ease-out going up and an ease-in coming down, like something thrown:

```tsx title="dock-icon.tsx"
<motion.div
  className="tile"
  animate={launching ? { y: [0, -20, 0] } : { y: 0 }}
  transition={
    launching
      ? { duration: 0.6, ease: ["easeOut", "easeIn"], repeat: Infinity }
      : appleSpring(0.3, 1)
  }
/>
```

### Mission Control and Launchpad

Mission Control spreads every open window out so none overlap, and puts each back where it was when you leave. On the web that's a layout animation on every window at once: give each window `layout` and switch the container between its normal positions and a grid.

## Quick Look

Pressing space on a file in Finder zooms a preview out of its thumbnail. Apps that use Quick Look get the same zoom by telling the panel two things: the thumbnail's frame on screen, and an image to zoom from.[^17] If an app can't give a frame, it returns `NSZeroRect`, and Apple's documentation says "this will produce a fade of the panel."[^17] So even Apple's own API falls back to a fade when there's no origin to zoom from.

This one fits the View Transitions API well, because a preview is rarely interrupted halfway and the thumbnail and preview are different elements in different parts of the page. The thumbnail takes the transition's name before the snapshot, then hands it to the preview inside the update:[^12]

```ts title="quick-look.ts"
export function openPreview(thumb: HTMLElement, show: () => void) {
  if (!document.startViewTransition) return show();

  thumb.style.viewTransitionName = "preview";

  document.startViewTransition(() => {
    thumb.style.viewTransitionName = "";
    show(); // renders .preview, which has view-transition-name: preview
  });
}
```

```css title="quick-look.css"
.preview {
  view-transition-name: preview;
}

::view-transition-group(preview) {
  animation-duration: 300ms;
  animation-timing-function: cubic-bezier(0.32, 0.72, 0, 1);
}
```

A name can only be on one element at a time, or "the transition will be skipped,"[^12] which is why the thumbnail lets go of it inside the callback. In React, `show` has to commit synchronously (with `flushSync`) so the new state is in the DOM before the browser takes its second snapshot. The curve is a placeholder of mine, not Apple's.

## Reduced Motion

With Reduce Motion on, iOS still transitions between screens, but "screen transitions and effects use the dissolve effect instead of zoom or slide effects."[^18] The point of every animation here was to show where something came from, and a dissolve keeps the change visible without moving anything across the screen.

Motion does the same thing in one line. With `reducedMotion="user"` on `MotionConfig`, it "will automatically disable transform and layout animations, while preserving the animation of other values like `opacity`."[^19]

```tsx title="providers.tsx"
import { MotionConfig } from "motion/react";

export function Providers({ children }: { children: React.ReactNode }) {
  return <MotionConfig reducedMotion="user">{children}</MotionConfig>;
}
```

That stops the zoom, but on its own the app would then snap open. So the app also needs an opacity fade for the reduced case:

```tsx title="app.tsx"
const reduce = useReducedMotion();

<motion.div
  layoutId={open.id}
  initial={reduce ? { opacity: 0 } : false}
  animate={{ opacity: 1 }}
  exit={reduce ? { opacity: 0 } : undefined}
  transition={reduce ? { duration: 0.2 } : launch}
/>
```

The genie draws on a canvas, outside Motion, so it has to check `prefers-reduced-motion` itself and fade the window out instead. The View Transitions version can skip naming the thumbnail when `matchMedia("(prefers-reduced-motion: reduce)").matches`, so nothing morphs and the page crossfades as a whole through the default root transition.

## What I'd Use

For anything that grows out of something else and can be interrupted, I'd use Motion's `layoutId` or `layout` on a physics spring converted from Apple's response and damping, with radii in `style` so they're corrected. For something like Quick Look, which opens and closes but rarely changes its mind halfway, I'd use a view transition and ship no JavaScript animation at all. The genie is the only one that needs drawing by hand, and it's the one I'm least sure matches the original.

None of these are exact copies, because Apple hasn't published the values, but each one keeps the rule from the 2018 talk: things leave the way they came.
